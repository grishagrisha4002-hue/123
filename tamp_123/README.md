# Многопользовательский Qt TCP Сервер и Графический Чат-клиент

Проект разработан в строгом соответствии с требованиями технического задания.

---

## Архитектура проекта

Проект разделен на модули:
- **`server/`** — серверное приложение (C++/Qt5):
  - `main.cpp` — точка входа, обработка системных сигналов завершения.
  - `myserver.h`, `myserver.cpp` — ядро сервера (`QTcpServer`), учет лимита (макс. 5 клиентов), веерная рассылка сообщений.
  - **`server/functions/`** — вынесенные функции и модули:
    - `logger.h`, `logger.cpp` — функции ведения логов в файл `server.log` и консоль (с перезаписью при старте и выключении сервера).
    - `protocol.h`, `protocol.cpp` — функции форматирования системных сообщений чата по ТЗ.
    - `client_handler.h`, `client_handler.cpp` — управление соединением сокета, регистрация ников, обработка команды `/name <НовоеИмя>`.
- **`client/`** — графический клиент с интерфейсом на Qt Widgets:
  - `logindialog.h`, `logindialog.cpp` — визуальное окно входа (IP, порт, никнейм).
  - `chatwindow.h`, `chatwindow.cpp` — визуальное окно чата (веерный чат, смена ника, счетчик онлайна).
  - `logviewer.h`, `logviewer.cpp` — отдельное визуальное окно просмотра логов с поиском/фильтрацией и экспортом.
- **`Dockerfile`** — файл контейнеризации на базе `alpine:3.14` с автосборкой и автозапуском.
- **`test_clients.py`** — скрипт автоматизированного тестирования (5 клиентов по очереди + 6-й лишний клиент).
- **`dockerhub_image_link.txt`** — текстовый файл со ссылкой на образ DockerHub для фиксации в Git.

## Пункт 9: Команды сборки и запуска Docker-образа

### 1. Сборка Docker-образа из Dockerfile:
```bash
docker build -t qt_tcp_server:latest .
```

### 2. Запуск контейнера с пробросом порта 5555:
```bash
docker run -d -p 5555:5555 --name qt_server_instance qt_tcp_server:latest
```

### 3. Просмотр вывода логов сервера в реальном времени:
```bash
docker logs -f qt_server_instance
```

### 4. Остановка и удаление контейнера:
```bash
docker stop qt_server_instance
docker rm qt_server_instance
```

## Запуск графического Qt-клиента (`client/`)

### Вариант 1 (через Qt Creator):
1. Откройте файл `client/client.pro` в Qt Creator.
2. Выберите комплект сборки (Kit) Desktop (Qt 5 / Qt 6).
3. Нажмите `Ctrl + R` (или зеленую кнопку «Запустить»).
4. В появившемся окне входа укажите:
   - **IP / Хост**: `127.0.0.1` (или IP сервера)
   - **Порт**: `5555`
   - **Никнейм**: например `Алексей`
5. Нажмите **«Подключиться»**. Откроется окно чата.
6. Вы можете запустить несколько копий клиента одновременно (до 5 штук) для имитации общения разных пользователей.
7. В окне чата доступна кнопка **«Просмотр логов»**, открывающая отдельное окно со всеми событиями и фильтром.

### Вариант 2 (из консоли qmake):
```bash
cd client
qmake client.pro
make          # или mingw32-make в Windows
./chat_client # или chat_client.exe в Windows
```

## Автоматизированное тестирование сценария ТЗ (`test_clients.py`)

Для демонстрации работы 5 клиентов, веерной отправки сообщений, смены ника и блокировки 6-го лишнего клиента:

1. Убедитесь, что сервер запущен (в Docker или локально на порту 5555).
2. Запустите тестовый скрипт:
```bash
python test_clients.py
```

Скрипт автоматически:
- Подключит 5 клиентов по очереди и зарегистрирует их ники.
- Отошлет веерные сообщения от каждого клиента.
- Сменит ник одного из клиентов через `/name`.
- Попробует подключить 6-го клиента и выведет полученный отказ: `Сервер занят. Пожалуйста, подключитесь позднее.` с разрывом соединения.
- Отключит одного клиента.

---

## Соответствие правилам ТЗ

- **Лимит**: не более 5 клиентов. При попытке подключения лишнего — сервер пишет, что занят, просит подключиться позднее и немедленно разрывает соединение.
- **Приветствие**: при подключении сервер запрашивает ник.
- **Подключение**: сервер пишет в чат и лог: `К чату присоединился 'Ник' (ID: [X]).`
- **Смена ника**: по команде `/name <НовоеИмя>` сервер уведомляет: `Клиент [ID] сменил ник на 'НовоеИмя'.`
- **Отключение**: при выходе клиента сервер пишет: `Отключился 'Ник' (ID: [X]).`
- **Информация о количестве**: при каждом подключении/отключении отправляется: `Текущее количество подключенных клиентов: X`.
- **Лог-файл**: `server.log` перезаписывается при старте и завершении работы сервера.
